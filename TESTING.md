# Package Validation and Testing Guide

This guide explains how to use `Test-NekoPackages.ps1` to validate and test packages generated by NekoRelease.

## Overview

The testing script performs two main functions:

1. **Validation**: Checks package structure, file formats, and required fields
2. **Testing**: Performs local installation tests for supported package managers

## Quick Start

### Validate All Packages

After running NekoRelease, validate all generated packages:

```powershell
.\Test-NekoPackages.ps1
```

This will:
- Auto-detect package managers in `.\packages`
- Validate file structure and content
- Test local installation (where supported)

### Validate Specific Package Managers

```powershell
.\Test-NekoPackages.ps1 -PackageManagers @("vcpkg", "Conan")
```

### Validation Only (Skip Testing)

```powershell
.\Test-NekoPackages.ps1 -ValidateOnly
```

### Testing Only (Skip Validation)

```powershell
.\Test-NekoPackages.ps1 -TestOnly
```

### Verbose Output

```powershell
.\Test-NekoPackages.ps1 -Verbose
```

## Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `PackagePath` | String | Path to packages directory (default: `.\packages`) |
| `PackageManagers` | String[] | Specific package managers to test (auto-detect if not specified) |
| `ValidateOnly` | Switch | Only validate, don't test installation |
| `TestOnly` | Switch | Only test installation, skip validation |
| `Verbose` | Switch | Show detailed validation information |

## Validation Checks

### Chocolatey

**Files Checked:**
- `*.nuspec` - Package manifest
- `tools\chocolateyinstall.ps1` - Installation script

**Validation:**
- ✓ Valid XML structure
- ✓ Required metadata fields (id, version, authors, description)
- ✓ Installation script contains `Install-Chocolatey*` commands
- ⚠ Warns about placeholder text

**Testing:** Not supported (requires admin and package server)

### Scoop

**Files Checked:**
- `*.json` - Scoop manifest

**Validation:**
- ✓ Valid JSON structure
- ✓ Required fields (version, description, url, hash)
- ✓ SHA256 hash format
- ⚠ Warns about placeholder URLs

**Testing:** ✅ Supported
- Uses `scoop install <manifest>` to test local installation
- Automatically uninstalls after test

### Winget

**Files Checked:**
- `*.yaml` - Winget manifest

**Validation:**
- ✓ YAML structure
- ✓ Required fields (PackageIdentifier, PackageVersion, etc.)
- ⚠ Warns about placeholder text

**Testing:** Not supported (requires package in Microsoft repository)

### vcpkg

**Files Checked:**
- `portfile.cmake` - Port definition
- `vcpkg.json` - Port manifest
- `usage` - Usage information (optional)

**Validation:**
- ✓ Valid CMake syntax in portfile
- ✓ Required vcpkg functions (vcpkg_from_github, vcpkg_configure_cmake, etc.)
- ✓ SHA512 hash present
- ✓ Valid JSON in vcpkg.json
- ✓ Required fields (name, version)

**Testing:** ✅ Supported
- Uses `vcpkg install --overlay-ports` with dry-run
- Validates port structure without actual installation

### Conan

**Files Checked:**
- `conanfile.py` - Recipe definition
- `conandata.yml` - Source data (optional)

**Validation:**
- ✓ Valid Python syntax
- ✓ ConanFile class present
- ✓ Required attributes (name, version, license, url)
- ✓ Key methods (source, build, package)
- ✓ SHA256 hash in conandata.yml

**Testing:** ✅ Supported
- Uses `conan export` to validate recipe
- Does not perform actual build

### Meson WrapDB

**Files Checked:**
- `*.wrap` - Wrap definition

**Validation:**
- ✓ Wrap type section ([wrap-file] or [wrap-git])
- ✓ Required fields based on type
- ✓ Hash format for wrap-file
- ⚠ Warns about placeholder text

**Testing:** Not supported (requires being in subprojects/ directory)

### Buckaroo

**Files Checked:**
- `buckaroo.json` - Package manifest

**Validation:**
- ✓ Valid JSON structure
- ✓ Required fields (name, license)
- ✓ Source location present
- ⚠ Warns about placeholder URLs

**Testing:** Not supported (requires package in registry)

### CPM

**Files Checked:**
- `*.cmake` - CPM configuration

**Validation:**
- ✓ CPMAddPackage command present
- ✓ Required parameters (NAME, VERSION, GITHUB_REPOSITORY/URL)
- ⚠ Recommends URL_HASH when using URL
- ⚠ Warns about placeholder text

**Testing:** ✅ Supported
- Creates temporary CMake project
- Tests CPM configuration syntax

## Examples

### Example 1: Full Workflow

```powershell
# 1. Generate packages
.\NekoRelease.ps1 -Version "v1.0.0" -PackageManagers @("vcpkg", "Conan", "Scoop")

# 2. Validate and test
.\Test-NekoPackages.ps1 -Verbose

# 3. Review results and fix any issues
```

### Example 2: CI/CD Pipeline

```yaml
# .github/workflows/release.yml
- name: Generate Packages
  run: |
    .\NekoRelease.ps1 -Version "${{ github.ref_name }}" -ConfigFile .nekorelease.json

- name: Validate Packages
  run: |
    .\Test-NekoPackages.ps1 -ValidateOnly

- name: Upload Validation Results
  if: failure()
  uses: actions/upload-artifact@v3
  with:
    name: validation-errors
    path: packages/
```

### Example 3: Pre-Submit Validation

```powershell
# Before submitting to vcpkg
.\Test-NekoPackages.ps1 -PackageManagers @("vcpkg") -Verbose

# Before submitting to Conan Center
.\Test-NekoPackages.ps1 -PackageManagers @("Conan") -Verbose
```

### Example 4: Custom Package Path

```powershell
.\Test-NekoPackages.ps1 -PackagePath "C:\MyProject\output\packages"
```

## Common Issues and Solutions

### Issue: "Missing required field: hash"

**Solution:** Ensure you've run NekoRelease with a valid release that has downloadable assets:

```powershell
.\NekoRelease.ps1 -Version "v1.0.0"  # Wait for release to be created and assets uploaded
```

### Issue: "vcpkg is not installed"

**Solution:** Install vcpkg:

```powershell
git clone https://github.com/microsoft/vcpkg
.\vcpkg\bootstrap-vcpkg.bat
$env:PATH += ";$(Resolve-Path .\vcpkg)"
```

### Issue: "Conan is not installed"

**Solution:** Install Conan via pip:

```powershell
pip install conan
```

### Issue: "Invalid JSON in manifest file"

**Solution:** Check for syntax errors:

```powershell
Get-Content .\packages\scoop\myproject.json | ConvertFrom-Json
# This will show the specific JSON error
```

### Issue: "Missing SHA512 hash"

**Solution:** This usually means the release assets weren't downloaded. Ensure:

1. Release was created successfully
2. Assets are uploaded
3. NekoRelease completed the hash calculation step

### Issue: "Placeholder text detected"

**Solution:** This is a warning that you have `REPLACE_WITH_` or similar placeholders. This happens when:

1. No release URL was available during generation
2. Running in Create mode without existing release

Update the files manually or re-run NekoRelease after creating the release.

## Prerequisites for Testing

Different package managers require different tools to be installed:

| Package Manager | Required Tool | Installation |
|----------------|---------------|--------------|
| Scoop | scoop | <https://scoop.sh/> |
| vcpkg | vcpkg | <https://vcpkg.io/> |
| Conan | conan | `pip install conan` |
| CPM | cmake | <https://cmake.org/> |

If a tool is not installed, the script will skip testing for that package manager but still perform validation.

## Integration with NekoRelease

### Recommended Workflow

```powershell
# 1. Configure NekoRelease
Copy-Item .nekorelease.example.json .nekorelease.json
# Edit .nekorelease.json with your settings

# 2. Dry run to preview
.\NekoRelease.ps1 -Version "v1.0.0" -DryRun

# 3. Actually generate packages
.\NekoRelease.ps1 -Version "v1.0.0"

# 4. Validate before submitting
.\Test-NekoPackages.ps1 -Verbose

# 5. If validation passes, submit to repositories
```

### Automated Testing Script

Create `release-and-test.ps1`:

```powershell
param(
    [Parameter(Mandatory=$true)]
    [string]$Version
)

# Generate packages
Write-Host "Generating packages..." -ForegroundColor Cyan
.\NekoRelease.ps1 -Version $Version -ConfigFile .nekorelease.json

if ($LASTEXITCODE -ne 0) {
    Write-Error "Package generation failed"
    exit 1
}

# Validate packages
Write-Host "`nValidating packages..." -ForegroundColor Cyan
.\Test-NekoPackages.ps1 -Verbose

if ($LASTEXITCODE -ne 0) {
    Write-Error "Package validation failed"
    exit 1
}

Write-Host "`n✓ All packages generated and validated successfully!" -ForegroundColor Green
```

Usage:

```powershell
.\release-and-test.ps1 -Version "v1.2.0"
```

## Exit Codes

The script returns the following exit codes:

- `0` - All validations passed
- `1` - One or more validations failed or package path not found

This makes it suitable for CI/CD pipelines.

## Troubleshooting

### Enable Verbose Output

```powershell
.\Test-NekoPackages.ps1 -Verbose
```

### Test Individual Package Manager

```powershell
.\Test-NekoPackages.ps1 -PackageManagers @("vcpkg") -Verbose
```

### Skip Testing (Validation Only)

Useful if you don't have package managers installed:

```powershell
.\Test-NekoPackages.ps1 -ValidateOnly
```

### Debug Specific Files

Check individual files manually:

```powershell
# JSON files
Get-Content .\packages\scoop\myproject.json | ConvertFrom-Json

# XML files
[xml]$nuspec = Get-Content .\packages\chocolatey\myproject.nuspec
$nuspec

# YAML files
Get-Content .\packages\winget\myproject.yaml

# Python files (conanfile.py)
python -m py_compile .\packages\conan\conanfile.py
```

## Best Practices

1. **Always validate before submitting** to package repositories
2. **Use verbose mode** when debugging issues
3. **Test locally** with supported package managers before submitting
4. **Run in CI/CD** to catch issues early
5. **Review warnings** even if validation passes
6. **Keep tools updated** (vcpkg, Conan, etc.)
